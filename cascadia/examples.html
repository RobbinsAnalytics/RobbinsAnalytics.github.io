01

Where AI enters the work.

A person brings the need. Existing work is checked before a new build. AI can help develop a solution within permitted context; people decide what enters and leaves the work.

Illustrative operating route

Check before building.

“Can this report show three more columns?” First confirm the business question, then inspect what already exists.

  • Use what existsAn existing report answers the question.
  • Resolve accessThe answer exists, but the requester cannot reach it.
  • Scope the workModify a certified view or define a new build only where needed.

Human entry: the requester confirms the question and useful result. An existing answer can close the request without a new build.

How the five capabilities support it

  • Sovereign GroundPermitted context and source traceability.
  • Foundation ReadinessBusiness definitions and expected answers.
  • Solutions FoundryCandidate queries, code and tests.
  • Experience FrameworkFindings a reader can inspect.
  • Trust AssuranceChecks, review and retained limits.
Illustrative application · synthetic data

When would a license reduction change the bill?

A requester needs to know when a reduction changes the bill. The agreed effective-date rule makes it effective at the next term boundary.

AI candidate

Subtract the reduced licenses from today’s billable quantity.

Rule and check

  • Rule: the current quantity stays billable through this term.
  • Check: a known case and separate calculation expose the early reduction.

Reviewed result: reject the candidate, correct the calculation and retain the failed case as a test.

This shows how AI assistance could be used with the synthetic scenario. The published Revenue Assurance module below demonstrates rule-based calculations; it is not presented as an AI agent.

The examples below show business rules, independent checks and operating records. AI-assisted work needs all three.

02

Make business meaning testable.

Trust begins with the rule the number is supposed to represent.

Synthetic subscription book

Cascadia Revenue Assurance

A customer requests a subscription reduction midway through a term. The order register reflects it immediately, but the bill does not change until the next term.Which quantity should be billed today?

The problem

  • Effective dates differ. Adds, reductions and cancellations follow different schedules.
  • A plausible number can answer the wrong question. Current quantity is not always billable quantity.

The delivered approach

  • Rules become executable logic. Python and DuckDB SQL independently apply the written timing rules.
  • Reconcile the results. State shared-rule and shared-input risks.

Where AI assisted

AI tools
Claude Code helped turn the written entitlement rules into separate Python and SQL calculations, then built four charts from Aaron’s staged brief.
Human direction and checks
Aaron reviewed the numbers before the visual build. Known cases and reconciliation checked the calculations.
Add licensesEffective immediately
Reduce licensesEffective at the next term boundary
CancelBillable through the existing term

Cascadia capabilities at work

  • Foundation Readiness

    Written entitlement rules define when a license change becomes billable.

  • Solutions Foundry

    Python and DuckDB SQL provide separate rule calculations.

  • Trust Assurance

    Known cases and reconciliation test the outputs; shared risks stay stated.

Reusable lesson

Meaning before calculation. A second derivation can expose disagreement; agreement still needs a clear statement of shared rules and inputs.

03

Plan for the next run.

Delivery includes what happens when data changes and a check fails.

Public federal court records

Cascadia Matter Ledger

A verified court-data model can be right at launch but drift as records arrive. Each later run must show what changed and what failed.How can the next run remain inspectable?

The problem

  • A valid snapshot is only a start. Later increments can drift.
  • Failures need a visible route. A silent run cannot support review.

The delivered approach

  • Freeze and verify the baseline; bound each scheduled increment.
  • Reassert, reconcile and publish check outcomes, including failures.

Where AI assisted

AI tools
Claude Code built the charts from Aaron’s specification and co-developed the live refresh pipeline, including the correction to save rows before moving its progress marker.
Human direction and checks
Aaron gave two rounds of chart feedback. Run records expose failures, and an independent calculation checks published measures.

Cascadia capabilities at work

  • Sovereign Ground

    Frozen, hash-verified court data anchors later increments.

  • Solutions Foundry

    The refresh saves rows before advancing its progress marker.

  • Trust Assurance

    Runs reassert invariants, reconcile results and report failures.

Reusable lesson

Operation is part of delivery. Preserve the baseline, define each run’s conditions and make failures inspectable.

04

Keep missing work visible.

Completeness depends on knowing what should exist, as well as what arrived.

Frozen synthetic demonstration

Cascadia Claim Integrity

A completed ride starts a chain of claim and reporting work. A missing downstream record can leave that work unfinished without an obvious failure.How can every expected step remain visible?

The problem

  • A ride record is not a claim. Construction needs supported facts.
  • Work continues after submission. Downstream obligations stay visible.

The delivered approach

  • Follow supported facts. Build the claim and check encounter readiness.
  • Keep expected work visible when a downstream record never arrives.

Where AI assisted

AI tools
Codex authored the source contracts, public fixtures, deterministic generator and foundation checks. Claude developed the application and interface.
Human direction and checks
Aaron approved foundation integration and made the owner decisions. Codex separately reviewed the completed candidate.

Cascadia capabilities at work

  • Experience Framework

    The claim journey distinguishes missing support, a corrected version and a recipient rejection.

  • Trust Assurance

    Readiness and missing downstream obligations remain visible for review.

Reusable lesson

Missing work stays in view. Model expected obligations as well as received records so an absent item cannot disappear from review.

05

What carries into the next application?

Three solutions, one repeatable discipline: test business meaning, inspect each run, and keep missing work visible.

  1. Define the meaning.

    Agree on the business rule and a known case that would expose a wrong answer.

  2. Keep evidence with the decision.

    Retain sources, checks, accepted limits and the accountable reviewer.

  3. Carry forward what was learned.

    Assign operation and recovery; evaluate feedback before updating the method.

Portfolio evidence has a boundary. These public or synthetic demonstrations show inspectable practices and outputs. They do not establish customer outcomes, implementation savings or a company-wide deployment.

The solution standard

A solution is useful when someone can accept it, explain it and revisit it.

Start with a confirmed question. Check the answer against its rules and evidence. Keep the decision and what was learned.
